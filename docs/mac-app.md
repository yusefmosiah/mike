# Mac app

**Status:** the Mac app is the iPhone app (`mobile/`) built for macOS with Mac
Catalyst. It builds, launches, and runs the speech plugin's dictation,
read-aloud and voice-mode models on this Mac (receipts below). Not accepted,
not signed with a Developer ID, and not yet at parity with the Electron app in
`desktop/` for window chrome, menus and connector sign-in. The owner decided on
2026-10-25: "Use Mac Catalyst and retire the Electron." `desktop/` stays until
the list in "Retiring desktop/" is done. History: [`goals/mission-18-mac-app.md`](../goals/mission-18-mac-app.md).

## Why Catalyst

The Electron app is a browser window around the hosted web app. The iPhone app
is the same window, plus native plugins: on-device dictation (Fluid Speech
Mini through FluidAudio on the Neural Engine, Apple's `SpeechAnalyzer`,
`SFSpeechRecognizer`), read-aloud (Phonon on Core ML, `AVSpeechSynthesizer`),
hands-free voice mode (`VoiceEngine`, Apple's voice processing for echo
cancellation, Silero VAD, Parakeet EOU, Smart Turn, the speaker models),
downloads and the camera. Building the iPhone app for the Mac gives the Mac
all of that from one code base, instead of porting each plugin to Electron.

## How it is built

`mobile/ios` is generated by `npx cap add ios` and git-ignored. Everything
below is applied by scripts, so it survives `npm run sync` and a fresh
`npm run ios:add`:

- **`scripts/configure-ios.mjs`** (`npm run ios:configure`, also run by
  `ios:add` and `mac:deps`), marker `MIKE_MAC_CATALYST`, App target only:
  `SUPPORTS_MACCATALYST = YES`, device family `1,2,6` ("Optimize for Mac":
  native Mac controls at 100% scale, not a scaled iPad), the iOS bundle
  identifier on the Mac too (`DERIVE_MACCATALYST_PRODUCT_BUNDLE_IDENTIFIER =
  NO`), and, under the macosx SDK only, `App/App-MacCatalyst.entitlements`,
  the hardened runtime and dead-code stripping. The Mac deployment target
  follows `IPHONEOS_DEPLOYMENT_TARGET` 18.0, which is macOS 15 under Catalyst:
  the floor the models already need. Newer APIs keep their `#available`
  checks (`SpeechAnalyzer` needs macOS 26; older systems use
  `SFSpeechRecognizer`). iOS builds read none of the macosx-only settings.
- **Entitlements** (written by the same script): App Sandbox, outgoing
  network, microphone (`com.apple.security.device.audio-input`), camera,
  files the person picks, and `~/Downloads`. `Info.plist` already has the
  microphone, speech-recognition and camera strings; the speech-recognition
  one now names the device through `$(MIKE_DEVICE_NAME)` ("iPhone", or "Mac"
  in the Mac build), so the iPhone's text is unchanged.
- **`scripts/build-mac-catalyst.mjs`** (`npm run mac:deps`): two binary
  dependencies ship without a Catalyst slice. Capacitor's
  `Capacitor.xcframework` and `Cordova.xcframework` (capacitor-swift-pm 8.5.3)
  have iPhone and simulator slices only; the script builds the Catalyst slice
  from Capacitor's source at the same tag (it compiles unchanged). xn-ptts's
  `PhononCore.xcframework` (0.4.0) has a macOS slice, which cannot be linked
  into a Catalyst app; the script builds `aarch64-apple-ios-macabi` from
  xn-ptts's source at the pinned commit with the toolchain its release used
  (Rust 1.99.1, installed by rustup for this build only). Every download is
  checked against the SHA-256 that Swift Package Manager pins. The output,
  in `ios/App/MacCatalyst/`, is two local Swift packages named like the
  remote ones, holding the releases' own iOS slices byte for byte plus the
  new Catalyst slice. `configure-ios.mjs` adds them to the Xcode project
  while they exist; a local package overrides the remote package of the same
  name for the whole build, so the iOS app links exactly the binaries it
  linked before (checked: the device build's `Capacitor` binary has the
  release's SHA-256) and the Mac build finds its slice. Without
  `mac:deps` the project is the iPhone project as before.
- **`SceneDelegate`** (marker `MIKE_MAC_CATALYST_SCENE`): the window's
  minimum size is 800×600 (the Electron app's; it keeps the web app above its
  768px mobile breakpoint), the title text and toolbar are hidden, and the
  title-bar code that already existed for the iPhone app on a Mac now keys
  on `isMacCatalystApp` (true for both). The privacy cover waits until the
  window leaves the screen (hidden or minimised): a Mac window stays visible
  behind other apps, and covering it on every focus change would only hide
  it from its user.
- **`plugins/files`**: on the Mac a download is saved to `~/Downloads`
  (` (2)` names, never overwriting), as in the Electron app; the share sheet
  there offers neither Files nor Finder.
- **`plugins/speech`**: one fix. A Swift package's resource bundle keeps its
  files in `Contents/Resources` on macOS, so the Fluid Speech Mini lookup now
  goes through `Bundle.resourceURL`; before it, the Mac app reported the
  bundled model unavailable.

Apple silicon only, like Phonon itself and the Electron build.

## Build and run

Needs Xcode, Node.js 22+ and rustup. From `mobile/`:

```bash
npm install
npm run ios:add            # first time (or npm run sync + npm run ios:configure)
npm run mac:deps           # Catalyst slices; a no-op when current (~5 min first time)
npm run mac:build          # Debug; scripts/build-mac.sh Release for a release build
open ios/App/build-mac/Build/Products/Debug-maccatalyst/App.app
```

`mac:build` signs ad hoc ("Sign to Run Locally") from the command line and
leaves the project's signing settings alone. In Xcode, pick the "My Mac (Mac
Catalyst)" destination; that needs a development team for the Mac (Xcode
offers to register the bundle identifier for Mac Catalyst).

The equivalent command, from `mobile/ios/App`, in a clean environment (a Nix
or Homebrew dev shell's `LD`, `CC` or `SDKROOT` breaks xcodebuild; see
`mobile/README.md`):

```bash
env -i HOME="$HOME" PATH=/usr/bin:/bin:/usr/sbin:/sbin \
  xcodebuild -project App.xcodeproj -scheme App -configuration Debug \
  -destination 'platform=macOS,variant=Mac Catalyst' -derivedDataPath build-mac \
  CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM= build
```

**First launch on a Mac that ran another build of `com.firm.mike`:** the
sandbox container belongs to the app that created it. A build with a
different signature (an ad-hoc build after a team-signed one, or the reverse)
waits at launch for macOS to ask whether it may use that data, before any
window appears. Answer the prompt, or test with another bundle identifier
(`scripts/build-mac.sh Debug PRODUCT_BUNDLE_IDENTIFIER=…`).

## What works (2026-10-25, macOS 27.2, Xcode 27.1)

Checked in the built app against a local harness page that calls the plugins
through the Capacitor bridge, as `deviceSpeech.ts` does (sandboxed, ad-hoc
signed, another bundle identifier for the reason above):

| Check | Result |
| --- | --- |
| Launch, window, web view, network in the sandbox | yes; 1024×768 window, `Capacitor.getPlatform()` is `ios`, user agent "Macintosh" |
| Plugins registered | `MikeSpeech`, `MikeFiles`, `Camera`, `App`, `Preferences` (and `@capacitor/browser`, tried) |
| Apple's recognizer | `status`: `available`, `speech-transcriber`, en-US. `transcribe` of a spoken clip: exact, punctuated, 0.8 s |
| Fluid Speech Mini | `status`: `available`, `live: true`. `transcribe`: exact; the first call took 68 s (Core ML compiling the model for this Mac), later ones are fast |
| Apple voices | 185 voices; `speak` returns a WAV |
| Phonon | `install` downloaded the model (20 s), `speak` returned a WAV in 0.3 to 0.6 s, `remove` deleted it: the Catalyst build of PhononCore runs |
| Voice mode models | `voiceInstall` fetched VAD, EOU, Smart Turn and the speaker models (437 MB with Phonon, 45 s); `voicePrewarm` loaded them all (`ready`: eou, fluid-mini, phonon, smart-turn, speaker, vad); `voiceRemove` deleted them |

Not checked, because each needs a person at the Mac: the microphone prompt
and a live dictation (`startLive`) or voice session (`voiceStart`) with
Apple's voice processing (echo cancellation), the camera, and how the window
looks (this terminal has no Screen Recording permission). The audio code has
no Catalyst-specific branches: `AVAudioSession` and
`AVAudioInputNode.setVoiceProcessingEnabled` exist on Catalyst, and the
microphone entitlement and usage string are in place.

The iOS build still builds (simulator and device, unsigned), with the local
packages in place.

## What is left

**Before the Mac app can replace Electron:**

1. **Connector sign-in popups.** The web app opens connector consent with
   `window.open("about:blank")` and waits for the callback's
   `window.opener.postMessage`. Capacitor's WebKit delegate answers every
   `window.open` by handing the URL to the system (`UIApplication.open`) and
   returning no window, so the page gets no popup, on the iPhone and the Mac
   alike. Electron kept popups in a child window with a live opener. Fix in
   the shell: return a child `WKWebView` from
   `webView(_:createWebViewWith:for:windowFeatures:)` (a sheet on the iPhone,
   a second window on the Mac), fenced like Electron's (http(s) only, no
   bridge); or move connector OAuth to `ASWebAuthenticationSession` with a
   `mike://` callback, which needs a backend change. Check main's
   `@capacitor/browser` work (`SFSafariViewController`) against this: it
   compiles under Catalyst, but a Safari view has no opener either.
2. **Menus and shortcuts.** Catalyst gives the standard menu bar (app, Edit
   with undo, copy, paste and spelling, View with full screen, Window, Help).
   The Electron menu's ⌘N, ⌘1 to ⌘6, ⌘, and ⌘⇧H (`desktop/src/main.js`)
   need `buildMenu(with:)` in `AppDelegate` with `UIKeyCommand`s that tell
   the page to navigate (`evaluateJavaScript`).
3. **Window chrome.** Hidden title text is set; whether the unified window
   controls sit over the page as on an iPad, and whether the page needs
   Electron's `--mike-titlebar-inset` strip (`AppSidebar.tsx`) to keep the
   sidebar logo clear of the traffic lights and to drag the window, has to
   be checked by eye.
4. **The page calls the Mac a phone.** The web app labels the device engines
   "This iPhone" and its messages say "this phone"
   (`frontend/src/app/lib/voice/`); the edge-to-edge layout code
   (`displayEdge.ts`) assumes a phone. The page needs to know it runs on a
   Mac (the plugin could report it, or the "Macintosh" user agent with the
   bridge present) and word these for a Mac.
5. **Downloads other than `MikeFiles`.** Downloads that go through the
   `MikeFiles` plugin land in `~/Downloads`. A plain link to a signed
   document URL is not probed and saved as Electron did; check which
   download paths still bypass `nativeFiles.ts`.
6. **Changing servers.** Electron had a connection screen with ⌘⇧, to change
   servers at run time; the Capacitor app has its offline page and a server
   fixed at build time (`MIKE_SERVER_URL`).
7. **Signing, notarization, distribution.** A Developer ID Application
   certificate (or the firm's), the hardened runtime (already set for the
   Mac build), `notarytool` and stapling, then a signed `.pkg` through MDM
   (Apple Business Manager can assign a Mac app with the same bundle
   identifier). This Mac has no signing identity. The ad-hoc build runs only
   here.
8. **Voice mode in the background.** Voice mode ends when the app goes to
   the background, which on a Mac means hidden or minimised, not merely
   behind another window. That matches the iPhone; decide whether the Mac
   should keep listening.
9. **CI.** No job builds the Catalyst app; `mac:deps` needs Rust and about
   five minutes, so a macOS runner should cache `mobile/.cache/mac-catalyst`.

**Release hygiene:** the Catalyst slices are rebuilt from source, so a
Capacitor or xn-ptts upgrade must update `PINS` in
`scripts/build-mac-catalyst.mjs` (the script refuses a mismatch). If upstream
ever publishes Catalyst slices, drop the script and the local packages.

## Retiring desktop/

Do not delete `desktop/` until each of these has a Catalyst equivalent, or
the owner drops it:

- [x] Origin fence: only the server renders; other links open in the
      default browser (Capacitor's `allowNavigation` and
      `UIApplication.open`).
- [x] Minimum window size 800×600.
- [x] One instance (Launch Services opens one Catalyst app per bundle).
- [ ] Remembered window size and position: Catalyst restores scenes by
      default; check by hand.
- [ ] Right-click menu with spelling suggestions: expected from WebKit on
      the Mac; check by hand.
- [x] Downloads to `~/Downloads` through `MikeFiles`.
- [ ] Connector sign-in popups with a live opener (item 1).
- [ ] Menu shortcuts ⌘N, ⌘1 to ⌘6, ⌘,, ⌘⇧H (item 2).
- [ ] Title bar: traffic lights over the page and a drag strip (item 3).
- [ ] Downloads from signed document links (item 5).
- [ ] Change server at run time, or decide it is not needed (item 6).
- [ ] Signed and notarized build, distributed (item 7).
- [ ] The e2e coverage in `desktop/e2e/` (sign-up, popups, downloads,
      external links, menus) redone for the Catalyst app, by XCUITest or by
      hand.

Then remove `desktop/`, its row in the root `README.md`, and the
`--mike-titlebar-inset` code in the frontend if Catalyst does not use it.
The backend's connector popup header (`Cross-Origin-Opener-Policy:
unsafe-none` on the OAuth callback pages, ported for Electron) stays: any
popup with an opener needs it.

## Later: the desktop node

Beyond the app, the Mac can act as a node the server drives: a browser on the
user's machine, computer use, a live view on the phone, and a folder synced
with the workstation VM. See [the desktop node scope](reports/desktop-node-scope-2026-10-10.md).
Upstream's self-contained local mode (the whole stack on the Mac) was left out
of the Electron port and is not planned for Catalyst.
