# Computer use with open models and open harnesses (Windows/Linux), as of 2026-10-25

Legend: [V] = I fetched and read the primary source. [R] = reported by secondary source or search summary only. All benchmark numbers are vendor self-reported unless noted; no row on the Steel.dev OSWorld board is independently verified.

## 1. Open models

### Named by the user (all exist)
- **Kimi K3** (Moonshot). [V] https://github.com/MoonshotAI/Kimi-K3 : 2.8T total / 104B active MoE, 1M context, native image+video (MoonViT-V2), MXFP4 QAT. API July 16 2026, weights ~July 26-27 [R]. Self-claimed OSWorld-Verified 84.8 (vs Claude Fable 5 85.0, Opus 4.8 83.4, GPT-5.6 Sol 83.0); OSWorld 2.0 58.3 (Fable 5: 66.1). Harness for the score not stated; "works best with Kimi Code CLI". Thinking always on; must echo reasoning_content back in tool loops. License [V] https://huggingface.co/moonshotai/Kimi-K3/blob/main/LICENSE : custom "Kimi K3 License" (not MIT). Free use/modify/distribute; if you run a Model-as-a-Service business over $20M/12mo revenue you need a separate deal; "Kimi K3" must be shown in UI for products >100M MAU or >$20M/month; internal use and embedding in an end-user product are outside the MaaS clause. Practical: ~1.5 TB weights, vLLM recipe wants 8x GB300-class (https://recipes.vllm.ai/moonshotai/Kimi-K3 [R]). No independent reproduction found [R].
- **DeepSeek V4.1 Flash** [V] https://api-docs.deepseek.com/news/news260910/ : released 2026-09-10, 552B MoE (8B/16B active in/out), "native visual understanding", weights at huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash. The post says nothing about GUI/computer use and states no license (MIT reported by third parties [R]). Upgraded to V4.1-Flash-1017 on 2026-10-17 [R, changelog https://api-docs.deepseek.com/updates/]. No OSWorld number found: treat as not a computer-use model.
- **GLM 5.3 / 5.3 Flash** (Z.ai). [V] https://docs.z.ai/guides/vlm/glm-5.3-flash : Flash is 320B/18B-active, 1M context, image/video input, release 2026-08-26 [R, release notes]. Docs claim CUA/BUA (click, type, multi-step) but give no action format, no OSWorld. Page does not link weights or name license (MIT on HF reported [R], unverified). Flagship GLM-5.3 (~744-753B) weights status conflicting [R]. Earlier GLM-5V-Turbo: OSWorld 62.3 (2026-04-01, self-reported, open status uncertain).

### Benchmarks and the gap
- OSWorld-Verified (Steel board, updated 2026-10-11) [V https://leaderboard.steel.dev/leaderboards/osworld/]: closed top ~85.0-85.4 (Claude Mythos/Fable 5); open 82.0 (MiMo) / 84.3-85.2 (Qwen3.8-27B, Holo4, per model cards). On this saturated benchmark the open gap is roughly 0-3 points by vendor claims, with all caveats on harnesses/step budgets.
- OSWorld 2.0 (108 long-horizon cross-app tasks, partial credit; arXiv 2606.29537 [R]) is where the gap reappears: Fable 5 66.1, GPT-5.6 Sol 62.6, Kimi K3 58.3, Holo4-27B 61.7 (own harness) on the partial metric [V model pages]; on strict binary pass rates, closed best ~20-31%, open best ~4.6 (MiniMax M3) on one board, Agent S4 + Qwen3.8-27B 21.3 on "OSWorld V2" [V Agent-S README]. Metrics are mixed across sources; do not compare across them.
- WindowsAgentArena: no 2026 open-model leaderboard found; only the 2024 Navi baseline (19.5% vs 74.5% human) [R]. Windows-specific open-model evidence is therefore thin; OSWorld is mostly Ubuntu.
- Independent verification: none found for Kimi K3, Qwen3.8, MiMo, Holo4.

## 2. Harnesses
- **Pi** [V] https://github.com/earendil-works/pi : MIT, minimal extensible harness by Mario Zechner (project moved to Earendil in spring 2026 [R]); packages pi-ai (multi-provider LLM API), pi-agent-core, pi-coding-agent, pi-tui, pi-durable, chord. No built-in computer use, no built-in permission system (runs with user's rights; sandbox via Docker/Gondolin). Computer use arrives as packages: **@agent-sh/computer-use-linux** [V https://github.com/agent-sh/computer-use-linux] (MIT, Rust MCP server, installs via `pi install npm:@agent-sh/computer-use-linux`; tools get_app_state, get_tree_page, screenshot, click, drag, scroll, press_key, type_text, perform_action, set_value, window mgmt; AT-SPI tree + screenshots; 739 stars; GNOME Wayland validated on Ubuntu 25.10 only). Fork **oh-my-pi (omp)** [V https://github.com/can1357/oh-my-pi] has a built-in `computer` tool (Rust: xcap capture, enigo input, OS accessibility FFI AX tree; linux/win32/darwin builds), scripted via persistent JS (`computer.window(), win.screenshot(), win.ax(), el.press(), computer.run()`), which is a code-as-action design that batches many steps per model turn. NOTE: this repo already runs its chat engine on Pi Durable (AGENTS.md), so Pi is the natural harness.
- **DeepSeek Harness (`dsh`)** [V https://www.deepseek.com/en/harness/] : MIT, public preview, announced 2026-08-13 [R], Cordis plugin architecture, desktop app/web UI, plugins for scheduled tasks, terminal, subagents, "Creator mode". No computer use on the page; only V4.1-Flash shown. Computer use only via community plugin (macOS-strong) [R]. Not a CU option today.
- **opencode**: no native desktop control; open feature request https://github.com/anomalyco/opencode/issues/20490 ; third-party MCP "opencode-computer-use" is macOS Swift [R]. **Goose** (Linux Foundation, MCP-extension based): no first-party CU found [R]. **OpenHands**: browser/code sandbox focus, no desktop CU found [R]. Use any of them with an MCP desktop server.
- **Agent S3/S4 (Simular)** [V https://github.com/simular-ai/Agent-S] : Apache-2.0, Win/Mac/Linux. S3 72.6 OSWorld with Behavior Best-of-N (66 single run, 100 steps); S4 released 2026-10-20, evolves its own tool interfaces, 21.3 binary on OSWorld V2 with Qwen3.8-27B. Most credible open research harness with open-model numbers. Best-of-N multiplies cost.
- **Cua** [V https://github.com/trycua/cua] : mostly MIT (Spaces and some bench parts FSL-1.1-MIT; cua-som AGPL), Cua Driver for macOS/Windows/Linux (native app control, tool schema not documented on page), Linux/Omarchy sandboxes, Cua Bench, CUA-S1 small models. Windows sandbox status unclear.
- **UI-TARS Desktop / Agent TARS** (ByteDance, Apache-2.0) [R]: Electron app plus 1.5-7B local model; older (2025) design; skip as base.
- **Windows-MCP (CursorTouch)** [V https://github.com/CursorTouch/Windows-MCP] : MIT, Win10/11, Python 3.14+. Tools: Click, Type, Scroll, Move(drag), Shortcut, Wait, WaitFor, Screenshot (fast, no tree), Snapshot (UIA interactive-element IDs + optional screenshot/DOM), App, PowerShell, FileSystem, Clipboard, Process, Registry, MultiSelect/MultiEdit, DisplayInventory, etc. Bearer auth/TLS/OAuth for remote, telemetry on by default. Bounded tree capture added in v0.8.5 [R].
- **Action patterns seen:** (a) element-ID actions from an a11y tree (Windows-MCP Snapshot, computer-use-linux get_app_state) so models need weak grounding; (b) coordinate actions from screenshots (needs a strong grounding model: Holo/Qwen3.8/Kimi); (c) code-as-action scripts (omp, Holo4 "shell on the desktop"). Context control: cheap Screenshot vs expensive Snapshot split, bounded trees, WaitFor polling instead of re-screenshotting, memory mechanism (Holo4). Verification: post-action state re-read; Kimi/GLM thinking-always-on models need reasoning_content passed back.

## 3. Control layers
- **Windows**: UIA (Windows-MCP uses it for Snapshot), SendInput-style input, PowerShell. Microsoft's own: Agent Workspace (separate contained session/account with its own desktop, Agent ID, scoped known-folder access, MCP proxy audit) and the Windows On-device Registry (ODR) of MCP connectors. [V https://support.microsoft.com/en-us/windows/ai/ai-features/experimental-agentic-features] says: experimental, off by default, admin-enabled, private preview for Insiders, builds >=26100.7344, last updated 2025-12-05; agents "click, type and scroll like a human"; UIA not mentioned. Native MCP preview in 26220.7344 with File Explorer and Settings connectors; broader taskbar rollout in April 2026 is [R] only. Not usable as GA infrastructure for a third-party agent; our native app should use UIA + SendInput directly. Caveats: UIPI (cannot drive elevated windows), secure desktop/UAC, session 0 isolation.
- **Linux X11**: xdotool/XTEST, AT-SPI, EWMH. **Wayland**: RemoteDesktop portal + libei (GNOME 46+, KDE 6.1+; one-time approval, restore token; US-layout typing limits; native Wayland windows not targetable on GNOME) [V https://github.com/zavora-ai/computer-use-mcp/pull/49, dated 2026-10-25, unmerged-status unknown]; ydotool/uinput fallback; KWin libei without dialog (kwin-mcp, kde-mcp [R]); Hyprland lacks RemoteDesktop portal [R]; wlroots/Sway weakest. Screenshots via Screenshot/ScreenCast portal; black-screen edge cases on multi-monitor.
- **Remote**: RDP/VNC give a pixel-only path with no a11y tree; no 2026 open-model-specific findings, so I did not research further.

## 4. System 1 / System 2 and "Jev"
- **Jev is real** (spelling correct): TypeSafe AI's "System One Model", introduced 2026-09-15 [V https://jevai.net/articles/what-is-system-one-jev/ , an unofficial community site; second source https://www.mindstudio.ai/blog/jev-system-one-model-launch dated 2026-09-18]. Founder named Diogo/Diego Almeida, described as ChatGPT/RLHF co-inventor (claim not verified). It is non-autoregressive: returns typed decisions with probability and calibrated confidence, ~0.114 s and ~$0.00008 per call, vendor claims of ~100-190x faster/cheaper than LLMs. API only; open status not stated. It is not a computer-use model and does not see screens or emit coordinates; it is a fast decision/gating primitive.
- **CUA-S1** (Cua) is the computer-use derivative inspired by Jev [V HN https://news.ycombinator.com/item?id=49767564]: 706k-param CUA-S1-FORMS, chooses use-value/CHECK/CLICK/SKIP per form field, no screenshots, 99.7% vs hosted Jev 83.6% on their set, 7-9 ms local; MIT code in trycua/cua `libs/cua-s1`, weights on HF per the repo README. Narrow, early.
- Closest real planner+grounder patterns: OSWorld-Human (arXiv 2506.16042) describes planner LLM + smaller grounding VLM; Agent S family (generalist planner + grounding model, now plus Best-of-N); GTA1; UI-TARS/Holo-style grounders paired with a larger planner. Sensible split for us: slow planner = Kimi K3 / Qwen3.8 / API model; fast grounder/actor = Holo4-35B-A3B (3B active) or a Qwen3.8-27B-class model; a11y tree first, pixels second; tiny CUA-S1-style classifiers for deterministic sub-decisions.

## Gaps and cautions
- Every score above is vendor-reported with differing harnesses/steps/effort; Steel notes none are independently verified. I could not read the Holo4 27B license, MiMo licenses, GLM-5.3 license/weights, UI-Venus-2, or the official XLANG OSWorld leaderboard directly.
- Several search-result summaries contained mutually inconsistent dates/figures (flagged [R]).
- Wayland/Windows open-harness maturity is hobby-grade (hundreds of stars, single-distro validation).
