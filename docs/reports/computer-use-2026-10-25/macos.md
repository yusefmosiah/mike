# Open-source computer use on macOS, state of the art (as of 2026-10-25)

Method: 3 rounds of WebSearch/WebFetch. Caveat on verification: WebFetch returns a small-model summary of each page, not raw source. I did not clone repos or read code or commit logs. Everything below is therefore "reported by the page cited", not "verified by reading source". Where a page gave no date, I say so. Vendor benchmark numbers are self-reported unless noted.

## 1. Control layer on macOS

### How open projects drive a Mac
| Approach | Who | Notes |
|---|---|---|
| AX tree + screenshots + background input via private SkyLight SPIs | **Cua Driver** (trycua/cua, MIT; open-sourced 2026-04-22) | Rust runtime, ships as signed `CuaDriver.app`. Action ladder: AX actions, then pixel clicks, then brief window raise with focus restored; reports confirmed / unverifiable / likely no-op after each action. Uses undocumented SkyLight (`SLEventPostToPid`, focus-without-raise) and private AX SPIs. Needs macOS 14+. Source: [Cua blog, 2026-07-13](https://cua.ai/blog/computer-use-2-ai-engineer-worlds-fair), [repo](https://github.com/trycua/cua), [DeepWiki](https://deepwiki.com/trycua/cua/6-cua-driver:-background-computer-use) (third-party). Risk: Apple can change SkyLight symbols in any OS release. The repo's own page did not name SkyLight; that comes from the Cua blog and third-party writeups. |
| AX tree + OCR + CGEvent, background-capable, signed helper | **apple-cua** (trac3r00, MIT) | Observation tokens (input only against a fresh snapshot of the exact window), explicit app targeting, global stop chord, `doctor` command. Also drives iPhone via iPhone Mirroring. Needs Accessibility, Screen Recording, Automation. Small, unproven project; read for design ideas. [repo](https://github.com/trac3r00/apple-cua) |
| AX-first MCP servers | **Peekaboo** (openclaw/Peekaboo, MIT, v4.9.7 mentioned; `see` returns element IDs, background-only by default, `agent` mode), **Open Computer Use** (iFurySt, MIT, modeled on Codex computer use), **MacOS-MCP** (CursorTouch, MIT, PyObjC, bearer-auth HTTP so usable for remote Macs), **mcp-server-macos-use** (mediar-ai, Swift, last commit 2026-04-26), **mac-computer-use** (iamngoni, Swift, AX + CoreGraphics + ScreenCaptureKit) | [Pinggy roundup](https://pinggy.io/amp/blog/best_computer_use_mcp_servers/), repos linked in it. Peekaboo and Open Computer Use pages gave no release dates. |
| Screenshot + coordinates only | **computer-use-mcp** (domdomegg, nut.js), Anthropic reference style, UI-TARS Desktop | Simple, works anywhere, slowest and least reliable. |
| First-party | **Claude Code / Desktop computer use** (research preview, closed), **Codex Mac app background computer use** (2026-04-16, [9to5Mac](https://9to5mac.com/2026/04/16/openais-codex-app-adds-three-key-features-for-expanding-beyond-agentic-coding/)) | Closed, but show the target UX: per-app approval, hidden other apps, Esc to abort. Codex mechanism is unconfirmed (blogs disagree between AX and screenshots; one says SkyLight). |
| Agent frameworks that embed a driver | **Hermes Agent** (Nous) uses cua-driver over MCP; modes standard / bounded / unrestricted; SoM screenshots for vision models, `ax` mode for text-only. [docs](https://hermes-agent.nousresearch.com/docs/user-guide/features/computer-use) | Good reference for approval UX. |
| Full agents (framework + model prompts) | **Agent S3/S4** (Simular, Apache-2.0, runs on macOS/Win/Linux), **UI-TARS Desktop** (ByteDance, Apache-2.0, 39k stars, but "no repo news since Nov 2025" per Simular's comparison, i.e. stale), **Microsoft UFO** (Windows focus), **Self-Operating Computer** (old), **Open Interpreter** (moved to coding agent) | [Simular comparison](https://platform.simular.ai/compare/open-source-computer-use-agents), dated 2026-10-22; Simular is Agent S's vendor, so treat the framing as biased. |

Not found: a current Goose or "macOS-use"/browser-use desktop effort of note. Browser Use remains browser-only.

### Apple's own surface (verified by reading Apple's WWDC26 macOS guide via fetch)
- No computer-use API and no MCP in macOS 27 per [WWDC26 macOS guide](https://developer.apple.com/wwdc26/guides/macos/). What shipped: App Intents entity/intent schemas for Siri, View Annotations (map views to entities so Siri can act on on-screen content), LongRunningIntent, an App Intents Testing framework, Foundation Models framework (can host non-Apple models such as Claude/Gemini), Core AI for local models, and an `fm` CLI. Secondary claims (SiriKit deprecated, Siri on Gemini) are unconfirmed.
- Implication: App Intents is a structured, permission-clean channel for apps that adopt it; it does not remove the need for AX/screen control for the long tail.

### TCC / permissions (consistent across all projects)
- Needs Accessibility (input + AX tree) and Screen Recording (capture). Automation (Apple Events) for AppleScript. Grants attach to the signed app identity that owns the process, not the binary path. Hence Cua Driver, apple-cua and Claude all push a signed helper `.app` so one grant is reused (Cua docs via fetch; Hermes docs; apple-cua README).
- Stale grants are a real support burden: Hermes docs tell users to run `tccutil reset Accessibility com.trycua.driver` then re-grant. Screen Recording often needs a process restart after granting (Claude Code docs).
- A grant can only be given by a human at the machine; no MDM-free programmatic route. For a shipped Mac app: sign + notarize, keep one stable bundle ID, build an onboarding that deep-links to the panes and a `doctor`-style status check.
- Private SkyLight use probably rules out Mac App Store distribution; fine for Developer ID distribution. This is my inference, not stated by sources.

### Virtualization
- Lume (Cua) uses Virtualization.framework for macOS/Linux VMs on Apple Silicon; setup automation drives Setup Assistant via VNC + OCR ([X post early 2026](https://x.com/trycua/status/2013287181566288101), [issue #1215](https://github.com/trycua/cua/issues/1215) proposing a CUA agent to replace brittle presets).
- Hard limit: 2 concurrent macOS guests per host (licence, enforced by the framework; Linux guests exempt) ([Lume limits doc](https://cua.ai/docs/reference/lume/limits), [Eclectic Light](https://eclecticlight.co/2023/09/14/current-limitations-on-macos-virtual-machines-running-on-apple-silicon-macs/); background, 2023). I found no source on iCloud in VMs or on Tart specifically.
- Relevance: VMs are for sandboxed testing/eval and unattended tasks, not for controlling the user's real Mac (which is our core product).
- Cua Cloud (Fleets) reportedly ended 2026-10-18 (Cua blog). The OSS stack is MIT, but Cua Spaces is FSL-1.1-MIT, `cua-som` is AGPL-3.0, and `cua-perception` has AGPL model artifacts: check licences before bundling.

## 2. Perception and models

### Perception findings
- Convergent pattern across Cua Driver, Peekaboo, Hermes, typesafe-computer-use: AX tree first (cheap, exact), screenshot with set-of-marks numbered elements for vision models, OCR as supplement, pixel-coordinate grounding as fallback for canvases/Electron/games. apple-cua adds `analyze_screen` for windows whose AX tree is blind.
- Claude Code downscales screenshots (3456x2234 to ~1372x887) and warns that small UI text suffers.

### OSWorld numbers (note the three different benchmarks)
- OSWorld-Verified (short tasks, ~2 min human time): open-weight leaders reported are Qwen3.8 Max 86.1 (2026-10-20, self-reported, listed as open weights by one board, treat with suspicion), Kimi K3 84.8 (2026-07-27), **Qwen3.8-27B 84.3** (released 2026-08-14, reportedly Apache-2.0; run on one GPU, ~17 GB at 4-bit), **Holo4-27B 85.2** (H Company's own harness, 2026-09-28). Best independently measured open entry cited: 80.4 (Muse Spark Open). Sources: [BenchLM](https://benchlm.ai/benchmarks/osworld-verified), [LLM Stats](https://llm-stats.com/benchmarks/osworld-verified), [H Company](https://hcompany.ai/newsroom/holo4). Harness, step budget and self-reporting explain disagreements ([Wavect](https://wavect.io/blog/qwen3-8-27b-self-hosted-computer-use-agents/) explicitly says tables are not comparable across harnesses). Closed: Claude Opus 4.8 83.5 (from the OSWorld 2.0 paper).
- Background (older, 2025): OpenCUA-72B 45.0, UI-TARS-1.5 42.5, GTA1 45.2 with o3 planner, Agent S3 72.6 best-of-N. The field jumped roughly 40 points in a year, driven by general VLMs (Qwen3.x) trained with RL on computer use.
- **OSWorld 2.0** (June 2026, 108 long-horizon tasks, 500 steps; [arXiv 2606.29537](https://arxiv.org/html/2606.29537v1)): best closed Opus 4.8 20.6% binary / 54.8% partial; GPT-5.5 ~13%. Open: Agent S4 with Qwen3.8-27B 21.3% ([arXiv 2610.28601](https://arxiv.org/abs/2610.28601), 2026-10-20), Holo4-27B 61.7% by H's own metric (metric/steps not stated; likely not comparable), Holo4-35B-A3B 30.9% (one source says 34.5%). Takeaway: short-task OSWorld is nearly saturated; long-horizon state tracking is the real gap (agents spend under 7% of budget on verification and often ignore mid-task messages).
- **macOSWorld** ([arXiv 2506.04135](https://arxiv.org/abs/2506.04135), 2025, background): 202 tasks, 30 apps, 5 languages, a safety/deception subset. Proprietary CUAs >30%, open-source research models <5% then. I found no 2026 leaderboard update. This is the only Mac-native benchmark and is stale, so we should expect to build our own macOS eval (Cua-Bench is the nearest tool).
- Grounding (from [perea.ai survey](https://www.perea.ai/research/gui-grounding-models-2026), secondary): ScreenSpot-Pro best single open model UI-Venus-1.5-30B-A3B 69.6 (74.8 with zoom-in, Apache-2.0, Feb 2026); MAI-UI-32B (Microsoft) 67.9 and ScreenSpot-v2 96.5; UI-Venus-1.5-8B 68.4; MEGA-GUI system 73.2. ScreenSpot-v2 is saturated (~96). An aggregator lists Qwen3.8 Max at 84.5 on ScreenSpot-Pro (unverified, no primary source found). Older: GTA1-7B 50.0, Jedi-7B 30.1, UI-TARS-72B 37.1, OS-Atlas, ShowUI, UGround (2024-25, background only). UI-TARS-2 (47.5 OSWorld) and full UI-TARS-1.5 are not downloadable.
- Licensing traps: Holo4-27B is CC BY-NC (non-commercial); Holo4-35B-A3B is Apache-2.0; Qwen3.8 only the 27B is reported Apache-2.0 (sources conflict, one page showed a GPL label, likely template error; verify on the model card); OpenCUA is MIT.

## 3. System 1 / System 2 and "Jev"

**Jev exists.** Spelling was right.
- Jev is a hosted "System One" (decision) model from **TypeSafe** (typesafe.ai). It does not generate text; it returns a typed answer (choice, score, yes/no probability, with calibrated confidence) about a supplied state. Early access; page dated 2026-10-19. Price $0.042/M input tokens, output free. Latency reported 70-500 ms (their benchmark: 0.114 s vs 8.566 s for an LLM workflow). **Weights unpublished, so not open.** Available through OpenRouter, Vercel AI Gateway, Cloudflare Workers AI. Sources: [typesafe.ai](https://typesafe.ai), [awesome-system-one](https://github.com/andyrewlee/awesome-system-one) (community list, CC0; primary-ish for the ecosystem, but performance claims are vendor or third-party). Image inputs and a `box` bounding-box output are in a 1.14 preview behind opt-in headers (per the list; typesafe.ai itself did not mention them).
- Computer-use projects built on it: **typesafe-computer-use** ("jev", macOS, ~$0.0002/step: OCR of frontmost window + AX labels, a classifier picks the next action, a writer LLM is called only for free text; many forks, uses Quartz, AX, AppleScript, Vision OCR; needs Screen Recording + Accessibility for the terminal) ([awlevin repo](https://github.com/awlevin/typesafe-computer-use), I did not read the code); tiptour-macos; jev-ultrafast (browser, Google Flights in 7.1 s claim).
- **The open alternatives matter more for us.** Per the awesome list: Apache/MIT System One models (JevK5 4B/9B, Kev up to 27B, NanoJev 0.6B, Strands Decider on Gemma 4, Perplexity Decider V1.1 Apache-2.0, Base Labs mammoth-1 MIT, Liquid d1) and Apple-silicon ports (laya-mlx 7-14 ms on M3 Max, jevmlx, jev-foundation-models Swift bridge). Quality claims come from community benchmarks (JevBench, Decision Index) that the list itself notes are contested; none are computer-use-specific except Cua's.
- **Cua-S1** (trycua, announced via [X](https://x.com/trycua/status/2101014004927729737), [model card](https://github.com/trycua/cua/blob/main/libs/cua-s1/MODEL_CARD.md)): the first open System-One-for-computer-use family. CUA-S1-FORMS: 706K-param byte-level transformer, ~2.8 MB, MIT, ranks fixed candidate actions; Cua-S1-Nano-0.1 (855K params, Apache-2.0) and Cua-S1-4B-0.1 (LoRA on Qwen3.5-4B, 9 GB, 19-50 s per decision on M1 Ultra CPU, i.e. not usable yet). Input: AX tree excerpt or screenshot crops plus an enumerated option list (max 26). Honest status: the model card shows held-out cross-dataset accuracy of 0.0-0.57, with perfect scores only on same-distribution data. It is a research seed, not a general policy.
- Design lesson (consistent with UI-TARS paper's System 1/2 framing, background arXiv 2501.12326): System 1 = closed-set choice among options enumerated by deterministic code (AX elements x action types), with confidence-gated escalation to the planner. This only works when the candidate set is enumerable (AX-rich native apps, forms), and fails on novel UIs. Both Jev-style and Cua-S1 model cards say so.
- Also relevant: open-weight VLM policies that are fast enough on their own (Holo4-35B-A3B has 3B active params; Qwen3.8-27B dense is slower). No per-step latency numbers were published by any of them (H Company's page did not mention latency; Wavect gave none). V-JEPA / streaming-video GUI policies: I found nothing computer-use specific. Treat Jev as the intended referent.
- Related research seen but not read: Think Twice, Click Once (fast/slow grounding, [arXiv 2503.06470](https://arxiv.org/pdf/2503.06470), 2025, background); UFO3 speculative multi-action execution (51% fewer model calls, reported by Simular's page).

## 4. Security and safety patterns
Observed in shipping systems (documented in the cited pages):
1. **Per-app approval per session**, with sentinel warnings for terminals/Finder/System Settings; tiered control (browsers view-only, terminals click-only) (Claude Code docs).
2. **Global abort** that the agent cannot dismiss: Esc consumed by the harness (Claude); Ctrl+Opt+Cmd stop (apple-cua).
3. **Hide other apps and exclude the agent's own window from screenshots** so on-screen text can't loop back (Claude).
4. **Observation tokens / fresh-snapshot requirement** before any input (apple-cua, Peekaboo background-only mode).
5. **Approval classes and hard blocks**: destructive actions need approval; unattended runs refuse rather than auto-approve; blocklist for key combos (force delete, lock) and `curl | bash` type patterns; system prompt forbids clicking permission dialogs, typing passwords, following instructions on screen (Hermes). `bounded` mode = reviewed capability manifest of allowed apps/origins/tools; `unrestricted` only in disposable VMs (Hermes, Cua Driver).
6. **Single-session lock** (Claude); multi-agent separate session IDs/cursors (Cua Driver 0.8).
7. **VM isolation** for anything untrusted (Lume); not applicable to controlling a real user Mac.
8. **Human confirmation for irreversible actions** is recommended by Cua-S1 card, apple-cua ("tokens prove observation, not consent"), and Wavect.
Threat data: VPI-Bench reports visual prompt injection deceiving CUAs up to 51% with limited help from system-prompt defences ([arXiv 2506.02456](https://arxiv.org/pdf/2506.02456), 2025; figure via Wavect); OS-Harm ([arXiv 2506.14866](https://arxiv.org/abs/2506.14866), 2025); "Invisible Ink Threats" ([arXiv 2608.02018](https://arxiv.org/pdf/2608.02018), Aug 2026) and "Blind Spot of Agent Safety" ([arXiv 2604.10577](https://arxiv.org/pdf/2604.10577)): titles only, I could not read the PDFs. macOSWorld has a deception-attack subset (2025). OSWorld 2.0 shows agents under-react to injected messages, which is a different but related failure.
For a remote (phone to server to Mac) design, the extra surface is the transport: the Mac app should enforce policy locally (app allowlist, action classes, kill switch) rather than trusting the server. This is my recommendation, not from a source.
