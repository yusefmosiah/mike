## 1. Jev multimodal release
- [V] Blog "Jev: For the builders AND dreamers" https://typesafe.ai/blog/jev-1-14 (body dated 2026-10-14, page metadata 2026-10-19). `jev-1.14.0` available as `jev-preview` (experimental); `jev-latest` to point to it ~1 week later; 1.13.0 stays (60-day deprecation notice for 1.13.0, 30 for 1.14.0).
- [V] Images allowed anywhere the JSON interface accepts text (`state`, `instructions`, `criteria`), referenced via `assets`. Opt-in header `TypeSafe-Danger-Zone-Images: true`. TypeSafe itself says Jev does worse on images than text; split tasks into simple parts.
- [R] Search summary of same post: 1.13.0 "was multimodal all along" (hidden); 1.14.0 adds a `box` type returning a single bounding box (so coordinates are in scope for 1.14 only). Not seen in my own fetch of the post; verify before relying.

- CONFLICT [V]: https://docs.typesafe.ai/concepts/system-one.md still says Jev "currently accepts only text input"; awesome-jev (https://github.com/cobanov/awesome-jev) says hosted Jev is text-only (stale vs 1.14 preview). andyrewlee/awesome-system-one says image inputs in the 1.14 preview. Questions evaluated in parallel and in isolation, so more questions barely add latency. Docs index: https://docs.typesafe.ai/llms.txt. No SDK or endpoint spec seen.

## 2. Category: System 1 / System One / decision model
- [V] Definition (TypeSafe docs): fast structured decisions software can use directly; typed answers + probabilities, not text; calibrated across groups of predictions, not per answer. Names come from Kahneman (Thinking, Fast and Slow); no individual coiner stated. TypeSafe/Jev is "first". Tutorial says introduced 2026-09-15 [R https://analyticsmadesimple.com/tutorials/system-one-models-fast-decision-layer-for-software/]. Technique: single parallel pass, non-autoregressive-style scoring (some open ones read next-token distributions at fixed slots instead of decoding).
- [V] Docs advise using confidence to decide act vs escalate to a human or reasoning model. Docs do not describe an LLM planner pattern; that pattern comes from third parties.
- [V] Cua article https://x.com/trycua/article/2101437979180904640 (2026-09-19, only snippets via search [R]): asks how many decisions inside a computer-use agent need a general LLM; small model scores choices from an app-defined closed set; "an architecture to explore, not a shipped integration"; Jev cannot read screenshots or navigate unfamiliar apps (as of that date), and faster decisions do not fix bad perception, stale state, bad candidate menus or long-horizon planning [R].
- Prior art (older, academic): dual-process agents, e.g. https://arxiv.org/pdf/2503.06470 "Think Twice, Click Once" (fast/slow GUI grounding), https://arxiv.org/pdf/2502.11882. Not decision-model specific.
- Big-vendor entrants [R from awesome-system-one list]: OpenAI Decisions API, Perplexity Decider, Microsoft-Decision-1, Cloudflare Clef, Liquid d1, Snowflake, etc. The category is real and crowded; the list is community-curated and self-reported.

## 3. Open and hosted alternatives (source: https://github.com/andyrewlee/awesome-system-one, [V] read, self-reported)
Multimodal open weights relevant to GUI:
- OneJev (https://github.com/OmniJev/OneJev) [V]: 0.8B/4B/9B/27B on Qwen3.5 bases, Apache-2.0, text+screenshots+photos+video (video needs a separate backend). GGUF via llama.cpp (Q8_0 of 0.8B on HF); no MLX mention. First release 2026-09-27, v1.6 2026-10-17; 193 stars, 69 commits. Benchmarks are own held-out set / Decision Index 0.3 (27B 69.49, 4B 62.01, 0.8B 48.82). Young.
- Intern-Decision (https://huggingface.co/collections/internlm/intern-decision) [V]: 0.8B/2B/4B, image-text, ~3-5k downloads each, paper arXiv 2610.22131 (~Oct 2026). License not shown on collection page (list says Apache-2.0). No GUI claims, no GGUF/MLX seen.
- Liquid AI d1 (https://www.liquid.ai/blog/d1-open, 2026-10-07) [V]: d1-3B text+image (LFM2.5-VL backbone), d1-omni-600M experimental; license not stated on page; llama.cpp day-one; single question latency 8 ms RTX 4090, 30 ms Apple M5 Pro, 50 ms Jetson Orin Nano. No GUI demo, no vision decision benchmark. Best on-device story for Mac so far.
- GUI-Decisions-31B (https://huggingface.co/infinitylogesh/GUI-Decisions-31B) [V]: Gemma 4 31B + slot-reading LoRA, Apache-2.0; action/click point (256 bins/axis)/key/scroll from one forward pass; ~190 ms/step on RTX PRO 6000 (152 ms NVFP4 LoRA) vs ~520 ms JSON baseline on same model; ScreenSpot click 0.869, held-out AGUVIS steps 0.650. Single step, no memory; point predictions miss small targets. Too big for a typical Mac; a 2B variant is listed [R].
- Cua-S1 (https://github.com/trycua/cua/tree/main/libs/cua-s1) [V]: research seed, not general. cua-s1-forms 706K params (text only; 97.5% in-distribution, 29.3% on unseen labels), nano 855K, 4B LoRA adapters on Qwen3.5-4B (0.2 has multimodal adapter). Code MIT, weights Apache-2.0/MIT. Measured on Apple mps (M1 Ultra): 1-3 s text, ~6 s multimodal for 4B; needs 16 GB free; no MLX/CoreML. Outputs selected/reobserve/abstain/error. Not production.
- Others (list-only [R]): GEV-26B-Decide (multimodal, Apache), Jev-Omni (Gemma 4 12B, text/image/audio/video), xor (Juspay, Qwen3.6-35B-A3B LoRA), H2O-Lightning-4B, Kev (0.8B-27B, github.com/jaredpalmer/kev, modality not stated), Laya (HF/NandhaKishorM), Vev, Jev Visual (MLX/Qwen experiment, uncalibrated), OpenJevSwift/jevmlx (Apple silicon), Torchcast (CC BY-NC). Note "Kev" exists as a real repo, not vaporware by existence, but maturity unchecked.
- Hosted multimodal: OpenAI Decisions API (text or image), kettei/Sqwish, SubQ Snap, Celeris, Sage beta [R].
- Benchmarks: JevBench, Image JevBench v0.3.0, Jev Decision Index, Artificial Analysis Decision Index, TypedBench, DecisionRobust [R names only; I did not read any leaderboard]. No GUI-specific decision benchmark verified apart from ScreenSpot on GUI-Decisions.
- Caveat: nearly all numbers are self-reported, some projects are days old. Realistically usable today: GUI-Decisions-31B (GPU), OneJev/d1/Intern-Decision small sizes (experimental), none proven on GUI loops.

## 4. Computer-use systems built on decision models
- typesafe-computer-use (https://github.com/awlevin/typesafe-computer-use, MIT, macOS 14+, Windows experimental, beta) [V]: Vision OCR of frontmost window + accessibility-tree labels -> one TypeSafe request with three Choices (action kind, item, site) -> deterministic action -> re-capture is the only check. A bigger "writer" model only for free text or after classifier stops; never picks actions. Stops on done / low confidence / stall / step limit. Own measurements: classifier 0.13-0.38 s vs 5.2 s Claude Opus 5 on bare screenshot; ~1.5 s vs ~5.5 s end-to-end; $0.0002 vs $0.032 per decision; $0.003 vs $0.40-0.90 per 12-step task. Frontier model did date reading unaided, classifier needed deterministic date parsing. OSWorld integration exists (Linux/KVM), no score listed. Forks/mirrors exist; use awlevin upstream.
- system1-agents (https://github.com/ThinkFlowLab/system1-agents) [V]: stock agents whose model is a decision model; chat model keeps planning, typed values, final answer. Windows Calculator: 17.2 s vs 30.1 s (1.75x), 6.7x cheaper; browser Allrecipes 3.89x faster, 16x cheaper. Single tasks, no variance. Routing rule: arithmetic, deduction, free text stay with chat model; no confidence threshold or auto-fallback documented. Desktop via Cua Driver (Windows/macOS).
- computer-use-jev (macOS Accessibility API), tiptour-macos, mobile-jev (Android), jev-browser, jev-ultrafast [R, listed in awesome-system-one].
- Failure modes (all sources): perception gaps (OCR matches few real web labels, so DOM used in browser), stale state, bad candidate menu, arithmetic/dates, adversarial text on screen, schema-valid but wrong output, task-specific demos not general reliability, calibration is population-level not per-call.

## 5. Assessment for phone -> server agent -> desktop app
- Pattern fit: the proven shape is planner (LLM, server) + candidate generator (deterministic perception on desktop: AX tree + OCR, optionally crop screenshots) + fast chooser + deterministic executor + re-observe. Decision model picks among enumerated candidates, never invents coordinates (except GUI-Decisions-style grounding models).
- Where it runs: perception, candidate list, executor, re-observe verification, and the confidence gate belong on the desktop (latency, privacy, screen data stays local). The chooser should be local if open weights: small (0.8B-4B) multimodal models on Mac, e.g. d1-3B (30 ms on M5 Pro per llama.cpp claim), OneJev 0.8B/4B GGUF; expect 1-6 s for 4B multimodal on mps per Cua-S1 measurements, so a text-only AX-tree/OCR chooser is the realistic fast path. Hosted Jev would be a network hop to a third party that receives screen text; with network RTT its 0.1-0.4 s advantage shrinks, and 1.14 images are preview-only.
- Server: LLM planner/System 2, escalation target, free-text writer, long-horizon state, audit log, phone UI. Escalate on: low confidence, abstain, stall, re-observe mismatch, irreversible actions (always plan/confirm), unexpected app.
- Recommendations: (1) build the interface now as a thin "chooser" abstraction (state + options -> choice, probs, confidence) with the LLM as default implementation and log (state, options, LLM choice) to collect labeled data and shadow-evaluate any decision model before gating on it; (2) do not trust vendor calibration, calibrate thresholds on own traces; (3) treat multimodal Jev 1.14 as experimental (not in docs, flag-gated, TypeSafe says worse on images); (4) expect 1.5-6x real gains on routine steps, not 200x; claims come from single-task demos.
- Open questions not resolved: Jev 1.14 box output accuracy; any independent benchmark of decision models on OSWorld/ScreenSpot beyond GUI-Decisions; MLX/Core ML ports quality (jevmlx, OpenJevSwift not read); licenses on d1 and Intern-Decision; Windows/Linux support for most clones.
