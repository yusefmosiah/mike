# Mike is now a firm-owned private intelligence system

October seventh, twenty twenty-six. I am writing this the morning after two days of work that turned your Mike fork into a complete private deployment. Ten stations, one spine, every one of them landed on the main branch.

The news in one breath: the system you asked for is built and the tests prove it.

Here is where things stand. The fork you started with was a good legal application that still trusted the public internet by default. It is now a firm-owned system that refuses to leak. Private mode is a switch the operator throws, and once it is thrown the server will not talk to outside model companies, will not let users sneak their own keys around the policy, and will not let tools carry privileged text out to web services unless you name those services out loud. Conversations branch like a tree instead of running in one line. You can edit an old prompt and keep both histories. Dictation and read-aloud run against your own machines. The phone client has a hardened shell waiting. Scanned paper gets read by local character recognition. And overnight, the system can run diligence over a data room by itself, writing code only inside a sandbox that has no way to reach the network.

Tuesday afternoon I started at the foundation. The first station gave the document tools a live in-memory model of Word files, so every edit lands on one paragraph or table cell at a time instead of rewriting whole files. The second station added a self-check: after the model drafts, it diffs what changed and lints the document structure before you ever see it. These two were the quiet ones. Nothing to demo. But everything after them leans on the guarantee that the file on disk is always well formed.

Tuesday evening brought search and memory. The third station split web search into swappable providers with citation checks, so no single vendor owns your grounding. The fourth made long conversations survivable: broken tool calls get repaired in place, long reads are bounded instead of stuffed into context, and when a session grows too long it compacts itself the way the Pi harness does, keeping a summary and the live branch while the old tail sleeps. That lesson cost a day of scoping. I first designed the compaction around my own habits, then found your harness policy in the repo and rescoped to match it. Read what is already written before designing anything new. It sounds obvious. It saved the station.

Wednesday morning was the visible half. The fifth station replaced the flat chat log with the immutable message tree you asked for, edit-and-branch, regenerate, and a navigator with named branches, so one lawyer exploring an alternate argument never disturbs what another lawyer sees. The sixth put voice behind the server: dictation that fills the prompt box without submitting, because legal dictation always needs correction, and streaming read-aloud that starts before the answer finishes. Audio is disposable by default. Only the transcript stays. The seventh added the overnight mode, a classifier that routes each turn to the right behavior tier and guardrails that let pure computation run free while anything that mutates or reaches outward pauses for approval.

Wednesday midday was the trust half. The eighth station is the one your whole briefing pointed at. Strict private mode boots as a gate, not a preference. The confidential lane verifies hardware attestation before any request flows and keeps a receipt with no prompt text in it. If attestation fails the request fails, with no silent retry through an unverified path. I verified my understanding of the provider incident from the summer against the actual code before writing a line, and the design reflects it: trust the cryptography, not the vendor's account system. The ninth station gave the overnight worker its sandbox, frozen globals, time and size caps, zero network by construction, and a diligence job that walks a data room in bounded waves and writes its memo through the same document path your lawyers use. I was honest in the code about the one limit: the sandbox assumes your own model computing on your own data, not hostile binaries. If that threat ever changes, the isolation needs a redesign, not a patch.

Wednesday night closed it. The tenth station taught the system to read scans, chunk every document into searchable spans with a hybrid search that needs no outside embeddings, and wrapped the phone story in an enterprise shell with the biometric and backup rules spelled out. The mobile shell is a scaffold, not a tested app, and the report says so plainly. Claiming more would be the kind of lie that breaks trust later.

Three judgments shaped the whole run and I would keep all three. Keep the provider layer neutral and push trust into policy, so a new machine or enclave is configuration, not surgery. Never rewrite history, branch it, because in legal work the path you abandoned is evidence too. And default every new surface to closed: audio evaporates, cloud endpoints vanish, untrusted scans are marked rather than silently dropped.

The one thing worth remembering is this. The model was never the project. The boundary was the project, and the boundary now holds in code, in tests, and in the network rules behind them.

What I would do next, holding the phone: stand up the three live proofs in your office, the graphics machine, the confidential lane, and one scanned matter, then let real dictation and real paper grade the system before anything else. The code is ready to be measured.
